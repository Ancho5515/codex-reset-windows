# CodexReset for Windows

Codex Desktop 的 Windows 对话续作工具，基于 [boyso/codex-reset](https://github.com/boyso/codex-reset) 开发。它帮助用户在限额中断后继续选中的对话，后台检测可用额度，界面不显示余量、套餐或余额，账号切换可交给外部模型路由软件。本项目为非官方工具。

- 按项目分组展示对话标题、最后对话时间和状态，支持搜索与勾选。
- 支持手动续作、限额中断后的自动重试和系统托盘后台运行。
- 逐条处理已选对话，明确失败后自动重试，并在运行日志中显示每条对话的结果。
- 桌面对话被占用时，通过桌面队列提交继续指令并请求唤醒原对话。

## 安装

运行环境：Windows 10 / 11 x64，已安装 Codex 并登录账号。

下载本仓库源码，安装 .NET 8 SDK，然后在仓库根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

生成后，双击 `publish\app\CodexReset.App.exe` 即可运行，无需额外安装 .NET Runtime。

## 使用

1. 打开程序，查看对话列表。
2. 勾选需要续作的对话；双击对话可在 Codex 中打开。
3. 继续指令默认为 `继续`，修改后点击“保存指令”。
4. 点击“立即继续已选对话”进行手动续作，或勾选“限额中断后自动重试”，每 30 秒检查额度，在确认可用后恢复已选且仍因限额中断的对话。
5. 关闭窗口或点击“收起到托盘”后，程序继续后台运行；点击托盘图标可打开界面，选择“退出”可停止程序。

自动续作同时检查可用额度和对话最新一轮的限额错误。额度耗尽、状态未知或读取失败时暂停自动发送，后续刷新确认额度可用后继续；路由后台若不提供额度接口，也会暂停自动发送。每条发送前重新核对额度，成功提交后同一失败轮次不重复发送；若续作后仍因限额失败，等待账号变化或下一次确认额度恢复，避免循环发送。正在运行、已经完成或由用户停止的对话不会自动续作。每条对话独立计时，明确的提交失败会在后续刷新中重试。手动续作仍可直接触发。

每次检测重新核对当前账号，不沿用上次额度。Codex 内置换号或 Magpie 更新本地登录凭据、路由配置后，程序会重连后台再查询；读取期间发生变化时丢弃旧结果。本工具正在执行的续作会先等待结束，再重连。账号和余量均不显示。

Magpie 仅替换登录文件时，已运行的 Codex 会话可能仍使用旧账号，需要重新打开会话或客户端；参见 [Magpie 维护者说明](https://github.com/yetone/magpie/issues/1907#issuecomment-6139799327)。本工具覆盖本地登录凭据切换，未对接 Magpie 网关内部多账号路由的余量。

对话已由桌面 Codex 占用时，继续指令会加入桌面队列，并请求唤醒原对话。“已加入桌面队列”表示指令已提交，实际执行状态请在 Codex 中查看。

队列回执超时会继续核对原请求；入队后唤醒失败只重试唤醒。对话再次中断时也会核对已有队列消息，避免重复提交。

连接失败或续作未完成时，查看“运行日志”中的具体原因，点击“刷新”重试。若日志提示发送结果未知，先在 Codex 中核对是否已收到指令。

## 手动打包与发布

CI 仅构建和测试，不生成或保留安装包。只有明确需要打包时，才在 Actions → release → Run workflow 中手动填写版本标签并运行，或在本地执行上述 build.ps1。推送代码、创建 PR 和推送版本标签都不会自动打包。
