# 专注对话续作

**目标：** 界面隐藏账号及余量，保留后台账号和额度检测、对话选择、手动续作、额度恢复后的自动续作和托盘运行。

**方案：** 使用本地对话记录中的最新失败轮次识别 `usageLimitExceeded`。每 30 秒检查一次，逐条重新确认当前账号及可用额度，只向勾选且仍待恢复的对话提交继续指令。优先采用后台明确的使用许可，兼容旧版额度窗口；额度耗尽、未知或读取失败时不自动发送。当前文件凭据模式下，核对 `auth.json` 和 `config.toml` 的指纹，变化后重连本工具后台；读取期间变化则丢弃旧结果，凭据暂时占用视作未知。已有续作执行结束后再因登录变化重连。同一失败轮次成功提交后不重复发送；再次限额时等待账号变化或下一次确认额度恢复，未知额度不视作恢复事件。每条真正提交前再次核对账号、额度、实时选择、开关和失败轮次。手动续作仍可直接触发。

**约束：** 沿用 .NET 8、WinForms、现有设置及续作通道，不新增依赖；保留桌面队列、迟到回执核对、失败重试和逐对话超时。保留现有 `CodexReset.sln` 改动。验证使用隔离 SQLite 和 RPC，不向真实用户对话发送测试指令。

1. 保留后台账号和额度 RPC，将自动续作按对话失败轮次去重，并在发送前检查当前账号及可用额度。
   - 验证：额度耗尽、账号退出、账号不一致及接口失败时不自动发送；本地凭据变化时丢弃旧结果，重连后读取新账号；新一轮限额、失败、取消勾选、关闭自动续作及迟到回执不会造成重复发送。
2. 精简主窗口及 CLI，删除用量、计划、余额和恢复倒计时，更新使用说明及截图。
   - 验证：对话列表、搜索、勾选、指令保存和托盘仍可使用；CLI 不再提供用量查询。
3. 运行核心测试、Release 构建、四档布局检查及真实 Windows 窗口回归。
   - 验证：多对话失败重试、慢启动、桌面队列各仅提交一次；实际窗口显示最终精简界面。

验证结果：66 项核心测试通过；四档布局检查通过；生产窗口的额度耗尽/恢复、再次限额防循环、失败重试、慢启动、桌面队列、手动最新轮次去重和断线清理自动回归通过。本机真实 app-server 使用隔离的虚构 A/B 凭据验证了旧账号缓存及重连后读取新账号。新版 App/CLI 位于 `release/app` 和 `release/cli`，发布版窗口及 CLI doctor 检查通过；原 `publish/app` 的旧版仍在运行，未覆盖其 EXE。Windows-MCP 因桌面处于用户控制状态，未完成交互验证。真实账号额度恢复、Codex 内置换号及 Magpie 切号尚未进行端到端实测；未对接 Magpie 网关内部多账号路由的余量。
