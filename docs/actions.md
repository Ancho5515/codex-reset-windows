# codex-reset-windows 的 Actions 存储与触发规则

普通 CI 只执行构建和测试；功能分支使用 pull_request 验证，默认分支推送只运行一次，不再同时响应功能分支 push。连续 PR 更新会取消旧的只读 CI。文档修改不触发应用构建。

正式版本通过独立 release.yml 发布：推送 v 开头的版本标签，或手动填写标签。已有标签会检出该标签源码后测试和打包；新标签绑定通过测试的提交。安装包直接存入 GitHub Release，不重复上传为长期 Actions Artifact。原有 Release 文件不会被维护任务删除。

需要临时安装包时，手动运行 CI 并启用 package；产物仅保留 1 天。失败测试的诊断也保留 1 天。当前历史包清理会保留最近一次成功的默认分支安装包作为过渡，但其原有到期时间仍然生效。

Actions Artifact Maintenance 每周日北京时间 04:13 执行；相关 CI/日报结束后也执行。首次合并维护文件会执行一次。手动 mode=audit 只审计，mode=cleanup 清理。结果写入运行摘要和日志，不生成额外 Artifact。只处理超过 24 小时、已结束运行的已知产物；未知文件和邮件去重标记保留原生命周期；发现其他排队或运行中的任务时只审计。

修改保留天数只影响未来上传；历史产物通过上述分页维护逐项删除。释放空间与 GitHub 计费页面刷新可能不同步；删除也不会抵扣此前累计的存储使用量。缓存与 Artifact 分开管理，本次保留加速现有任务的依赖及行情缓存。
